# 幻灯片原文提取、图中文字与换行修复

## 一、证据优先级

1. **原始 PPTX 中可见且可编辑的文本框 / 表格 / 图表标签**：保留原词、句子与数字；使用位置信息判断归属模块。
2. **渲染后的整页截图**：确认原文在实际 PPT 的布局、图片/流程中的文字与阅读路径。
3. **原始 PDF 的文本层**：如只提供 PDF，可用于参考，但经常对多栏、跨行段落产生混排；必须结合页面图片。
4. **原 PPT 备注（Speaker Notes）**：如需保留，单独列出，不属于可见幻灯片原文。

PDF/PPTX 提取与视觉核对相互补充。**无法证明属于原文的文字，不能写到 A。**

## 二、把原文按视觉模块划分

- 一个模块是 PPT 上能独立讲完的可见内容单元，例如“三栏对比的左栏”、一个框图加其右侧说明、一组编号步骤、图表及相邻解释。
- 标题如适用于整个页面，放在 `**PPT 页面标题（原文）**`，不要强行在每个模块重复它。
- 对于“左上概念、右上图表、底部 Key Takeaway”：模块 01 左上概念、模块 02 右上图表、模块 03 底部结论。
- 表格内的每个**行和列**可独立保留，但不必为每行创建一个新的模块；必要时用 Markdown 表格或原文代码块保持。
- **不能根据提取器 XML 顺序盲目输出**：例如两栏顺序可能是左第一句、右第一句、左第二句……。回到截图纠正阅读路径。

## 三、正确修复断行

从 PPT 提取的可见换行，既有**真正的段落分隔**，也有“文本框宽度 / 软换行”造成的**视觉断行**。仅合并后者。

### 可以合并

原始提取：

```text
This is the first
example of a language
model.
```

清理后：

```text
This is the first example of a language model.
```

模块标题：

```text
Long-Term
Memory
```

若它实际上只是一个两行摆放的标签，清理为 `Long-Term Memory`。

### 必须保留结构

- 不同项目符号：`• Planning` 与 `• Memory` 各占一行。
- 分别编号的步骤：`1. Input`、`2. Encoding` 各占一行。
- 表格不同单元格及行、Key Point 区块，独立保留。
- 代码中的真实换行、数学公式的多行结构、流程图多节点：保持顺序与上下文。
- 对句子中的 `--`、括号、引号、百分数、型号，不删改原字。

### 特别注意

- `PowerPoint` 的文本框分行可能是**作者手工输入的换行**。只在截图确认它仍是同一句 / 同一标题时合并。
- 跨文本框的句子不能仅按左右位置拼接；需要页面视觉证据。
- 若一个区域含重复的形状/动画帧，核对是否真实重复出现，不能擅自去重。
- 对于图片上不可辨认的小字，标注“图中细字无法可靠辨认”，并保留截图。不要大量 OCR 猜测。

## 四、图中文字提取边界

- A 中优先保留会直接用于授课的可见节点，例如 `Query / Key / Value / Softmax / Output`、表头和数值。
- 如果图片来自论文，包含大量不可辨认的小字，不要把整篇论文内容补入图中文字；只抄**可确认的可见标签**。
- 照片本身没有文字，则 `**图中文字：** 无额外可见文字`；B 可描述照片概念，但不得说照片文字写了什么。
- UI 截图和模型产品页面随时间变化，但 A 只能忠实提取**截图上展示的内容**。

## 五、脚本输出限制

`scripts/prepare_slides.py` 会记录文本元素的尺寸和位置，`selectable_text.md` 中元素先按位置排序，供视觉模型快速定位。它不负责判断准确的视觉模块边界；不读取图片里烘焙的文字；不负责写英文讲稿。
